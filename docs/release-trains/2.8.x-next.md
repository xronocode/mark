### FIX-018

- Summary / reported / reproduction: Export→PDF aborted the app six times on
  2026-10-23 (02:57, 02:59, 14:52 on 2.6.0-era binaries; 15:01, 15:05, 15:06 on
  v2.8.0) — SIGABRT, foreign (Obj-C) exception unwinding into Rust; FIX-017's
  containment only moved the abort site (its own catch_unwind is in the 15:0x
  faulting stacks).
- Root cause (proven 2026-10-23 evening): C-61 sent
  `msg_send![print_info, setJobSavingURL:]` — a selector NSPrintInfo does not
  define (NSPrintJobSavingURL is a print-settings DICTIONARY key; SDK headers
  + live `respondsToSelector` == 0 via the ObjC probe). Every real macOS
  export since C-61 raised NSInvalidArgumentException. E2E never caught it
  (the backend is mocked there); cargo lanes never touched AppKit selectors.
- Fix: save URL through the print-settings dictionary; the save job runs via
  `runOperationModalForWindow` (the working panel path's pattern — plain
  `runOperation` from a run-loop callback deadlocks main, reproduced with the
  probe). FIX-017's containment and off-main watcher stay.
- Guard: `print_path_selectors_exist_on_live_appkit_classes` audits every
  selector this module sends against the live AppKit classes.
- Source commit: `1d14e6fb` (branch fix/pdf-export-objc-crash).
- Automated evidence: cargo test m052 17/17; V-M-052 scenario-5 rewritten +
  scenario-6 added; evidence chain in
