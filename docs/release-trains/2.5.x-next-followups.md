## Execution plan

### EP-01 — Repair FIX-008 before candidate selection

Create a dedicated `C-FIX-008-VIEWER-PAN-CUES` bundle. The normative behavior should be:

- Fullscreen tables remain read-only and use drag/pan as the single horizontal-navigation model.
- No native horizontal scrollbar or bottom track appears at Fit, 1:1 or intermediate zoom.
- Subtle left/right edge shadows indicate table content outside the visible stage.
- At the centered initial 1:1 position, both shadows may appear when both sides are clipped. At the left bound only the right shadow remains; in the middle both remain; at the right bound only the left remains.
- Fit shows the whole table with neither horizontal shadow.
- Vertical overflow and the sticky header remain usable and are verified independently.
- Diagram viewer behavior, inline table editing and C-TABLE-FOOTER geometry are non-goals.

Required evidence:

1. A regression that fails on `bae95a97` by proving the current bar has no meaningful horizontal navigation range or does not reveal a clipped last column.
2. Unit coverage for transformed-bound-to-shadow-state calculation at left, middle, right and fully fitted positions.
3. Chromium and WebKit block-viewer coverage: no horizontal bar; drag reveals the last column; shadow sides update after pan and zoom; Fit clears both.
4. Existing zoom, focus trap, export, vertical cap and sticky-header cases remain green.
5. A fresh isolated Mark Test artifact identified by source, bundle id and binary SHA-256, followed by owner acceptance of this exact scenario.

Only after this gate passes can FIX-008 return to the queued table. Because its rejected code shares `a2d77872` with accepted FIX-003..007, repairing forward is the preferred candidate strategy; selectively removing the whole commit would also remove accepted work.

### EP-02 — Fix the FIX-011 release blocker

Create a dedicated FIX-011 GRACE bundle with the owner-approved untitled-tab action model:

1. **Save & Close** — the default action. For Untitled it opens Save As; the tab closes only after the write succeeds. Cancelling or failing Save As leaves the tab and its content open.
2. **Discard** — a separate, non-default destructive action that closes without saving.
3. **Cancel** — a separate visible nondestructive action. Escape and the dialog close glyph have the same result.

Do not label the destructive action “Close” or default to any discard path. Existing modified files remain a regression boundary: their successful Save & Close and explicit discard behavior must stay intact.

Required evidence:

- component/store coverage proves three visible labels and three distinct results;
- browser coverage drives the real Untitled tab flow through successful Save As, cancelled Save As, failed Save As, Discard, Cancel, Escape and the close glyph;
- destructive/default styling is asserted, not inferred from button order;
- dark-theme FIX-007 styling remains green;
- fresh isolated artifact and owner acceptance precede release admission.

### EP-03 — Resolve the remaining `main` boundary: C-TABLE-FOOTER

The `bae95a97` native review partially accepted the visual scope: caption paint, counter/footer appearance and the fitting table without a stray width action/counter. Fit to page remained in Full width and is the only open owner-review scenario. Keep C-TABLE-FOOTER in this package, preserve the accepted visuals, add a deterministic transition/persistence reproducer, repair the host `fit` serialization gap plus the proven native cause, and present only that focused recheck. Queue only after it passes; otherwise the release session must construct and verify an explicit exclusion commit.

### EP-04 — Restore the Command Palette contract

FIX-010 is independent of the table work at the product level. Its own bundle must establish one authoritative ⇧⌘P route, open the existing root palette, close it with Escape, work under supported keyboard layouts, and never invoke paragraph duplication. Native-menu, renderer-command and global/editor key ownership must agree; the regression must press the real chord rather than only assert that duplicate does not claim it.

### EP-05 — Decompose FIX-009

Do not implement FIX-009 as one oversized change. Split it into at least two separately approvable bundles:

- **Startup session restore:** default-on “Restore last session on launch”, correct active tab/workspace roots, and a non-stale explicit action when the preference is off.
- **Recently closed tabs:** session-scoped bounded history, deduplication, reopen one/all, ⇧⌘T, empty-screen recovery and missing-file handling.

Workspace-root removal Undo and durable recovery of unsaved untitled drafts remain separate non-goals. The startup preference can land before recently closed history; neither blocks the FIX-008 release boundary.

### EP-06 — Keep large-document rendering deferred

Chunked first paint stays outside the stabilization wave until explicitly scheduled. Its future plan must preserve cursor/scroll restore, history, exports, search, outline and diff baselines while reducing a 1.7 MB document's first paint to the approved budget. The existing `BLOCK_OPEN_*` instrumentation is the before/after measurement surface.

## Package definition of done

This epic is complete when every inventory row is in exactly one explicit terminal handoff state:

- owner accepted and queued in a named release train with exact artifact identity;
- deliberately excluded from an exact candidate with reviewed source evidence;
- or deferred to a named backlog/change bundle with its reason and entry gate recorded.

No item becomes accepted through green CI, presence in `main`, or another feature's acceptance on the same binary. Publication remains a separate operation in the dedicated release session.
