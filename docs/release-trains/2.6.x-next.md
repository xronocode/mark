### FIX-013

Node >= 25 default-on experimental Web Storage breaks the local vitest suite (66 files / 841 opaque failures on the Windows polygon; zero product defects).

- **Reported:** Windows polygon bring-up (laptop-kari), 2026-10-20, `npm test` on Windows 10 22H2 / Node v25.8.1 / main@bae95a9: first failure `TypeError: localStorage.getItem is not a function` at `src/renderer/src/store/layout.js:5` plus 331 `--localstorage-file` worker warnings. Node 25 enables experimental Web Storage by default and its global shadows jsdom (Node CLI docs; vitest-dev/vitest#8757).
- **Owner decision (2026-10-20):** tooling-compatibility fix under M-046/V-M-046 — conditional `test.execArgv` for Node >= 25, a functional localStorage regression check, `.nvmrc` pinning the Node 22 reference runtime. The sidebar cold-start timeout stays separate; no global timeout raise.
- **Repair (C-FIX-013-NODE25-WEBSTORAGE-COMPAT, PR 17):** `vitest.config.ts` passes `--no-experimental-webstorage` to test workers only on major >= 25 — Node 22 (flag accepted since 22.4.0, Web Storage not default-on) needs nothing, and the gate keeps its worker arguments byte-identical; `tests/renderer/localstorage-webstorage-compat.test.js` pins function-typed Storage members and a set/get/key/removeItem/clear roundtrip.
- **Repair evidence:** local Node 22 run green (flag correctly absent); Windows polygon Node 25 full `npm test` with no NODE_OPTIONS override; the negative control proved the check detects the shadowed global; V-M-046 scenario-18 recorded.
- **Train/state:** `2.6.x-next` / repaired; owner acceptance pending on a fresh artifact.
