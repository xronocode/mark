### FIX-017

- Summary / reported / reproduction: SIGABRT ~370 ms after the
  Export-to-PDF save panel closed on 2026-10-23 02:57
  (`mark-2026-10-23-025710.ips`, Mark 2.6.0, macOS 26.6.2) — a foreign
  (Obj-C) exception unwound through tao's run-loop observer and Rust
  aborted by the foreign-exception rule; the `mt_export_pdf` command
  was completing at that exact instant. One occurrence in retained
  crash reports; the NSException reason itself was never recorded.
- Root-cause triage (2026-10-23): app-side catching of such exceptions
  is impossible on the current Rust toolchain (verified empirically —
  the `objc_exception` shim and objc's `"exception"` feature both abort
  before any Rust catch boundary), so the fix removes the dangerous
  configuration: the export print job runs detached
  (`setCanSpawnSeparateThread:YES`, wry parity) so `runOperation` no
  longer parks the main thread inside its nested run loop while tao
  observers fire mid-print; completion is watched off-main (15 s); both
  macOS command subtrees run under panic containment
  (`BLOCK_PRINT_GUARD_CAUGHT`). Boundary: a foreign exception under
  tao's own observer frames remains fatal — that boundary belongs to
  tao upstream.
- Source commit(s) / integration state: `426198d5` via PR #27,
  merged to main as `df84e93d` (2026-10-23); integrated.
- Automated evidence: `cargo test m052` 16/16 (new
  `print_path_panics_degrade_to_errors_not_app_death`), `cargo check`,
  V-M-052 vitest set 505 passed, `tests/e2e/print-export.spec.ts`
  chromium 3/3, `grace lint` clean; graph/verification deltas M-052 +
  V-M-052 scenario-5.
