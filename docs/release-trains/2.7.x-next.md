### FIX-017

- Summary / reported / reproduction: SIGABRT ~370 ms after the
  Export-to-PDF save panel closed on 2026-10-23 02:57 — a foreign
  (Obj-C) exception unwound through tao's run-loop observer
  (`control_flow_end_handler`) and Rust aborted by the foreign-exception
  rule; the `mt_export_pdf` command was completing at that exact
  instant. One occurrence in retained crash reports. Reason of the
  NSException itself was never recorded (Rust aborted first).
- Root-cause triage (2026-10-23): app-side catching of such exceptions
  is impossible on the current Rust toolchain — verified empirically:
  the `objc_exception` shim and objc's `"exception"` feature both abort
  before any Rust catch boundary. The fix removes the dangerous
  configuration: the export print job runs detached
  (`setCanSpawnSeparateThread:YES`, wry parity) so `runOperation` no
  longer parks the main thread inside its nested run loop while tao
  observers fire mid-print; completion is watched off-main (15 s);
  both macOS command subtrees run under catch_unwind containment
  (`BLOCK_PRINT_GUARD_CAUGHT`). Known boundary: a foreign exception
  raised under tao's own observer frames remains fatal — that boundary
  belongs to tao upstream.
- Source commit(s) / integration state: `72fef8ef` on
