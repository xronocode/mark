### C-TAB-CLOSE-OWNERSHIP

Keep the selected tab, editor body and subsequent edits owned by the same document after closing a tab.

- **Reported:** owner, 2026-10-19. Closing the active tab selected its neighbor while the editor retained the closed document. The earlier ordinary close checks passed; controlled timing exposed four independent ownership regressions.
- **Repair:** track the document actually rendered in Muya, reject late events from another or closed tab, reconcile a missed activation from the selected document, and prevent old-surface callbacks from writing into its neighbor.
- **Source / integration commit:** `943d57d69f7d3b9bf4f896b814649138470e01ac`, based on `0e8ffcd9299a7dd2b5ec25e3e677222cd2358960`. This delivery record directly follows the verified repair, preserving its runtime and test bodies. Source integration uses the ordinary guarded fast-forward push to `fork/main`.
- **Automated evidence:** [GRACE evidence](../../.grace/changes/active/C-TAB-CLOSE-OWNERSHIP/evidence.json), [unit regressions](../../tests/renderer/components/editor-coverage.test.js) and [session/browser regressions](../../tests/e2e/session-restore.spec.ts). Four new cases fail on the baseline. On the repaired combined base: 245 focused unit cases pass (two existing skips); full Vitest has 336 files, 4617 passed, two skipped and three todos; 20 Chromium/WebKit cases, renderer build and isolated native synthetic checks pass. GRACE current and selected target checks have zero errors.
- **Tested artifact:** the built renderer from source `943d57d6`, exercised in Chromium, WebKit and an isolated macOS WKWebView with a nonpersistent profile and Tauri shim. The sorted SHA-256 manifest of its 738 files has digest `efefe957d5887a95529903891fa6fb7bf01d66bd11f41fa7f5da6b4651606163` (each line: file SHA-256, two spaces, relative POSIX path, LF). `index.html` SHA-256: `cda946b665c01c72f9048c8dfee431635612fb288b0ed1c1901d6d7f9422b7f6`. This is a renderer test artifact, not an installed product build.
- **Owner acceptance:** 2026-10-19. After the verified repair was presented, the owner explicitly approved admitting `943d57d6` to the desktop release train. Accepted scope: closing to the previous/next tab, keeping the selected document visible, rejecting closed/background render events, recovering a missed activation and isolating subsequent edits. This is approval of the reviewed repair and recorded checks; it does not claim a separate owner live test or acceptance of other features in the base.
- **Limitations:** the original native producer/event sequence was not captured. Controlled native timing reproduces the same mismatch and verifies the ownership invariant; it does not exercise the full native backend.
- **Privacy:** public records and regressions use constructed examples only. Owner documents, screenshots, raw diagnostics and host paths stay outside public source. Normal exact-payload static, Gitleaks and two-pass local-model checks apply to commit and push.
- **Train/state:** `2.5.x-next` / queued. Candidate CI, complete train admission and release materials remain required. Version/date remain unassigned; publication needs a separate owner instruction.
- **Release note draft:** “Fixed the editor sometimes retaining a closed tab's content and assigning edits to the wrong document.”
