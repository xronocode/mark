## Scope as reviewed

Status `approved` (root attribute and `<Status>`), requirements R-1..R-7, eight
acceptance criteria, seven constraints, nine non-goals, four assumptions. The
bundle is `spec.xml` + `design-context.xml`; there is no `plan.xml`, which is
correct for a pre-plan bundle.

The change ships a UI-free renderer "mini-git" library: an in-memory per-open-document
append-only journal (in-app edit pause, external write batch, system rewrite), a
two-level diff over diff-match-patch, kind-level attribution, an external-write batch
policy, and the migration of `store/diffSnapshots.js` into a journal consumer. No UI,
no disk, no IPC, no Rust.

As scoped it is not one coherent change: the journal and its triggers, the
block-aware diff engine, the batch policy and the snapshot-store migration are
independently shippable, and a plan would still have to invent identity, retention,
coarse-unit and API decisions.

## Findings

### 1. Blocker — the approved bytes carry no recorded review

The bundle at this revision is exactly two files; the only review artifact in the
repository covers a different change and different bytes (`C-LARGE-DOC-STAGE-0`,
spec `33b0a8ad…` / design `fdcd0aef…`) and itself concludes that a fresh two-pass
review is required. Spec line 4 promises `grace-plan` only under the standing
four-corner gate.

Correction: record a review of these exact bytes with two consecutive clean passes,
or return the status to `draft`.

### 2. Blocker — the coarse diff layer rests on an identity that does not exist across recorded states

Muya block keys are ephemeral module-counter ids minted on every parse
(`src/muya/lib/utils/random.js:2-4`, `src/muya/lib/contentState/index.js:354`),
ring states keep markdown only (`src/renderer/src/store/diffSnapshots.js:54,77`),
`tab.blocks` exists only for the live parse (`editor.js:2049`) and is discarded on
reload (`editor.js:329`). A `diff(stateA, stateB)` can only re-parse and mint new
keys; it cannot return the keys those states had, and no consumer can map them to
DOM blocks. The spec defers this as a plan-time detail; the design context promises
block-level hunks for `ring[-2]`/`ring[-1]`.

Correction: define the coarse unit as content-derived (heading path + ordinal +
block type) or retain the block tree per state, and narrow the muya-key promise.

### 3. Blocker — the snapshot inventory is wrong and the stated migration would break the diff view

The spec claims two `recordSnapshot` call sites. There are four
(`editor.js:2474`, `2504`, `2535`, `2559`) plus two `recordOpenedSnapshot` calls
(`editor.js:336`, `1930`). `diffSnapshots` exposes eight exports, including
`recordOpenedSnapshot`, `openedSnapshot`, `SNAPSHOT_LIMIT` and `__resetDiffSnapshots`
(`diffSnapshots.js:40,75-87`), and `diffView` consumes both `latestSnapshot` and
`openedSnapshot` (`diffView.vue:34,166-167`).

Consequences: "ring-of-five semantics consumed by the existing diff view" is false;
`tests/renderer/store/opened-snapshots.test.js` and
`tests/e2e/diff-opened-baseline.spec.ts` fall outside the acceptance criteria; and
the two CONFIRM sites — the dirty-tab conflict branch — are unmentioned.

Correction: inventory all six call sites and both structures, add a requirement for
replaceable opened-baseline semantics, and extend acceptance to all four
diffSnapshots suites plus the opened-baseline e2e.

### 4. Major — stale references inside the live-defect claim

`editor.js:2212` is now `.trim()` inside `_EXPORT_DOCX`; the live-reload gate is at
`2458`/`2463` (function `2416-2573`). Four later commits shifted the file by +251
lines, so the design-context range now covers export code. The defect claim itself
is real; only the coordinates rotted.

Correction: cite semantic anchors (`APPLY_FILE_CHANGE`,
`START_BLOCK_SNAPSHOT_BEFORE_RELOAD_DATA`) instead of raw line numbers; refresh
`package.json:57` to `58`.

### 5. Major — several hidden changes plus undecided questions

Bundled: the journal and three triggers, the block-aware diff engine, the batch
boundary policy, the snapshot-store migration and a performance fixture/gate. The
dirty-tab repair is a further separate bundle. Undecided anywhere: journal identity
(tab id vs pathname, and rename-follow), close/eviction, `stateRef` representation,
how a system rewrite is detected (a formatter exists at `util/markdownFormat.js:44`
and `editor.vue:2477-2492` and is never named), how a formatter run followed by the
file write avoids a duplicate record, and the input contract that lets a UI-free
library apply hash-skip (which needs `tab.markdown`, `editor.js:2486`).

Correction: split into at least journal + batch-policy and diff-layer bundles, or
decide identity, retention, coarse unit and API shape in the spec.

### 6. Major — no memory bound; the retention acceptance is circular

R-1 keeps a full-content state per record, append-only; the design context chooses
full snapshots; the performance requirement gates elapsed time only, and the
acceptance says caps "behave as specified at plan time". Session memory is therefore
unbounded O(records × document size) for every open document, and
`C-LARGE-DOC-STAGE-0` R-4 already names journal retention as a memory input.

Correction: set caps (records per document, bytes per document, diff depth), evict on
tab close (`clearSnapshots` precedent, `editor.js:1416`), and add a retained-memory
acceptance bound with a number.

### 7. Major — `AffectedAreas` underdeclares the write scope

The in-app edit pause and the system rewrite need the muya `change` path
(`editor.vue:2746-2753` into `LISTEN_FOR_CONTENT_CHANGE`, `editor.js:1989-2049`) and
the formatter command (`editor.vue:2477-2492`). R-7 forbids new store actions, but
neither file is listed and the opened-slot site is missing.

Correction: list the exact files and anchors, or declare the seam that feeds the
triggers from existing tab state.

### 8. Major — untestable user-visible promises

The acceptance asks a unit test to pin that every kind "renders truthfully … with no
identity claim" while R-7 ships no UI; the requirement that recording and diffing stay
"off the critical rendering path" has no observable (the diff is pure and synchronous;
scheduling is caller-owned); "no regression in live-reload timings" has no baseline or
tolerance.

Correction: assert the record shape (`actor = {kind}`) and pin the absence of
label/confidence writers by source grep; state the scheduling rule with a measurable
check; move wording rules into the consumer bundles.

### 9. Minor — invalid role vocabulary

"library ROLE" is not in the protocol enum (`RUNTIME | TEST | BARREL | CONFIG | TYPES |
SCRIPT`); `diffSnapshots` uses `RUNTIME`. Correction: `ROLE: RUNTIME` with "library" in
PURPOSE, or extend the protocol first.

### 10. Minor — a private path cited in the spec

`spec.xml:4` cites `mark-private/backlog.md`, which contradicts the bundle's own
constraint and the privacy suite that retired `docs/backlog.md` for this reason.
Correction: "the owner-side backlog entry (2026-10-23)".

### 11. Minor — persisted data is defined; the privacy side effects are not

In memory only, per open document: full markdown per record, timestamp, `actor.kind`,
trigger, `stats{lines,bytes}` — acknowledged as no disk, no IPC, no telemetry. Not
acknowledged: full document text is retained for the whole session for every open
document, and nothing forbids content or paths in console logs and error reports,
while the reload path already logs filenames (`editor.js:2486,2516`).

Correction: limit diagnostics to `{tabId, trigger, stats}` — no content, no pathname,
no diff bodies — and state that the journal dies with the tab.

## Checked clean

XML well-formedness of both files; exactly one `C-*` wrapper; `<Change>` matches the
wrapper id; requirement and acceptance anchors are tags, not attributes; root and
child status agree; `AffectedAreas` and `VerificationIntent` present; no `plan.xml`;
no personal absolute path, secret or telemetry claim in the two files. The watcher,
settle-window, hash-skip, scroll-clamp, stale-block and notification-enum claims hold
against the current tree.

## Disposition

Open. The spec stays `approved` in this revision because demoting an owner-approved
artifact is an owner decision. Two defensible paths:

1. demote to `draft` and rewrite R-2, R-5, the snapshot inventory, the memory bound and
   the acceptance wording before re-review; or
2. keep the approval and treat this report as the checklist a plan must satisfy, which
   is only honest if the spec text is corrected first.
