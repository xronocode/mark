## Findings

### 1. Blocker — the approved status is not covered by any review of these bytes

`final-review.md:3-9` marks itself superseded and pins `33b0a8ad`/`fdcd0aef` at lines
17/19; the current files are `27df1bd6`/`be22602f`. That report also records the root
and child as `draft` (line 44) and requires a fresh two-pass review before planning.
There is no `<ApprovalBasis>` anywhere, and the spec still calls itself a "draft
bundle" (`spec.xml:30`, `design-context.xml:59`).

Correction: return to `draft` and record a two-pass review pinning the current bytes,
or add an explicit owner approval basis plus a review record for exactly these bytes.
The approved plan `f91378df` inherits the same gap.

### 2. Major — the design-context hash in the record is wrong

The current design bytes are `be22602f`. `7ff72017` is the pre-sanitization design in
commit `466d4c57`, which still contains the private path. Every record must cite
`be22602f` for this revision, and the sanitization must be carried into the canonical
copy together with a note of when and why it was applied.

### 3. Major — a private owner path still exists on the execution branch

`git show 466d4c57:.grace/changes/active/C-LARGE-DOC-STAGE-0/design-context.xml` line
22 named an owner-local research folder by path. `466d4c57` is
the head of local branch `spec/large-doc-stage0`, the branch the approved plan names as
its execution vehicle, and that plan claims "zero personal paths". The branch is not on
any remote.

Correction: apply the description-only text (or rewrite `466d4c57`) and re-run the
privacy scan **before** that branch is pushed. Do not push it as-is.

### 4. Withdrawn — the ExpectedCommand already routes the tiers correctly

An earlier draft of this review claimed the command chain could not execute because the
chromium project ignores `**/perf/**`. Re-reading the command shows the spec already
states that the Chromium bench tier runs through the bench driver "never a Playwright
project" and that the WebKit suites take `--project=webkit-perf --project=webkit-session`.
Withdrawn. The residual gap is that the driver still needs a build and a preview server;
the plan owns that.

### 5. Major — tail completion is both required and unmeasurable

R-9 asks the owner to approve a tail-completion budget, while R-4 and the acceptance
record tail-mount completion as explicitly not applicable until Wave A.

Correction: drop tail completion from the Stage 0 decision list and from the
acceptance, or define a proxy and make its budget a post-Wave-A gate.

### 6. Major — the durable landing place is undefined

R-9 and the acceptance require the approved contract to be recorded in "the owning
routed `.grace/context` document", but `.grace/context` holds five documents and no
index; `ux-guidelines.xml:34-37` only states the performance principle, and neither
`AffectedAreas` nor the plan's write scope names a context file.

Correction: name the exact document and add it to the write scope, or require a
separate governance bundle.

### 7. Major — the third "required" evidence tier has no executable gate

R-5 and the acceptance call the real-app WKWebView run required, but the command chain
has no real-app invocation, the evidence section leaves it outside CI as owner-reviewed,
and no marker set, artifact or pass criterion is defined.

Correction: specify command, artifact, markers and a pass criterion, or downgrade it to
optional owner-reviewed evidence.

### 8. Minor — the Save All transport is misnamed

`mt_save_tabs` appears nowhere in the tree. The unhandled transport is the
`mt::save-tabs` event (`src/renderer/src/store/editor.js:1068`, no Tauri listener); the
backend command that does exist is `mt_save_and_close_tabs`
(`src-tauri/src/m001_save_close.rs:352`).

### 9. Minor — the bench fixture is not ~6 KB

`src/renderer/bench/fixture.js` exports 3,992 characters / 4,002 UTF-8 bytes, about
4 KB.
