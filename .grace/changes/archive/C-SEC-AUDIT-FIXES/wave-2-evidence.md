## Implemented decisions

- Text insertion now resolves identity from a valid bearer belonging to an enabled `text.insert` extension. The shared incoming gate snapshots only applicable registry candidates, releases the registry lock, checks credentials on a blocking worker, and rechecks enabled/capability state before returning. Context/apply reuse this gate with their existing extension-id body and no invented capability requirement. Mark's text body remains `{text, source}`.
- LiveServerState, handlers, startup and all five event bridge helpers are generic over the Tauri runtime, with Wry as the production state default. Dev-only Tauri test support permits actual handler/event tests on MockRuntime. Neither main.rs nor mt_paths.rs changed, and listener, pairing-confirmation and stream-session designs are unchanged.
- Disable fences the registry before native credential work. It revokes persistent and memory storage and then proves absence from both. Entry creation, deletion, read-back and memory-lock failures propagate instead of becoming absence. A surviving secret or unavailable backend produces only the stable IPC error `ext_disable_revoke_failed`; details stay in the BLOCK_DISABLE_REVOKE_FAILED log. Tests inject per-extension credential backends; a test binary has no OS credential backend factory.
- The gallery retains the localized refusal after its list refresh. The single new `extensions.disableFailed` key exists at the top level in all ten shipped locale tables. An interaction test proves the message remains visible while the extension is shown disabled.
- Manifest and both outgoing sites share typed URL parsing. Only http(s) with parsed 127.0.0.1, localhost or ::1 hosts is accepted; userinfo, including an empty explicit authority marker, is refused. Final endpoints retain the protocol's concatenation but must preserve the parsed base origin. All redirects are refused by both clients. Both clients disable proxy discovery so an accepted local recipient cannot be routed through an environment proxy. These are the bounded implementation choices enforcing the already-approved recipient invariant, not a new extension protocol.
- `url = "2"` promotes the already locked parser; Cargo.lock changes only the Mark dependency edge. No new crate or dependency version is introduced.
- The [paired-client disposition](paired-client-disposition.md) records exact inspected TokMo references and the source-bounded no-supported-production-text-insert-caller decision. It does not substitute the Mark body fixture for deployed-client interoperability proof.

## Executed proof

1. Real full-bin `cargo test --offline --locked --jobs 2 --manifest-path src-tauri/Cargo.toml --bin mark m045` passes **63 tests**, with zero failures and the pre-existing ignored 30-minute synthetic smoke unchanged. All **19 required wave-2 named tests** appear in the executed output; the approved anti-vacuity guards remain intact.
2. Text-insert gate bypass on the disposable source copy fails five of the six named route/event tests: no token, wrong token, disabled extension, missing capability and requester identity. Restoring the gate returns the six-test set to green. Disabled/missing-capability fixtures perform zero credential reads; the authorized single-candidate fixture performs one.
3. Removing only strict post-delete absence verification makes `disable_refuses_unverified_revocation` fail when a backend read error is falsely reported as successful disable. The restored implementation proves confirmed persistent NoEntry alone is insufficient while memory holds a token; delete failure leaves a still-valid persistent token fenced on all three routes; entry/read-back failure and surviving-secret cases report failure. Actual disable, enable and fresh-pair handlers restore the legitimate path without accepting the old token.
4. The redirect test exercises actual HTTP behavior on owned fixture listeners. With each client's redirect policy independently removed, the test fails: invoke accepts the second fixture's JSON response, or health probing follows the second fixture and returns healthy. Restoring both policies rejects the 307 responses and leaves the second listeners uncontacted. Honest invoke receives its dummy payload/bearer, and an honest health request succeeds without Authorization.
5. The final i18n/gallery selection passes **72 tests across five files**. Removing post-refresh error retention from the disposable Vue fixture makes the new interaction regression fail because the refusal message disappears. Restoring it returns the suite to green. No native IPC is used in that interaction fixture.
6. Test execution uses a disposable full-project byte copy, not a reduced Rust harness. Source bytes were matched to the candidate; code/toolchain/registry/dependencies are read-only. Only scratch and Tauri's generated-schema subtree inside that disposable copy are writable. The Rust launcher supplies an empty allowlisted environment, two Cargo jobs, direct compiler paths, process/CPU/memory/disk/wall limits, and no external network. For HTTP tests, the parent reserves six listener ports and one dummy proxy port, passes owned listener descriptors, and grants only those exact ports. Deliberate dummy proxy settings receive no contact. No host credential backend, production caller or external endpoint is exercised.
7. Normal production `cargo check --offline --locked --jobs 2 --manifest-path src-tauri/Cargo.toml --bin mark` also passes under confinement, including the native keyring adapter excluded from test builds. It took 209.27 seconds with the separate check artifacts built from the local registry. All 57 tracked Rust/config inputs in the disposable project matched the candidate.
